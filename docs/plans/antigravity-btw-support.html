T3 Code: /btw Ephemeral Side-Question Support for Antigravity

Provider: Google Antigravity Harness: ACP / Gemini Flash Spec Status: Architecture & Implementation Plan

1. Motivation & Feature Concept

In agentic coding workflows, users frequently have quick contextual questions mid-turn (e.g. "What port does Vite run on?", "Did we define the user session schema with email?"). Currently, asking any question in T3 Code appends a turn to the active session, which either interrupts the running turn or waits for completion and irreversibly inflates the session token window.

The /btw ("by the way") command is a dedicated mechanism originating in CLI agents (Claude Code, Google Antigravity CLI agy) to execute an out-of-band, single-turn query that:

  • Causes Zero Context Drift: Dismissing the response leaves no record in state.sqlite or the model's message history.
  • Executes Mid-Task Without Interruptions: Runs concurrently even when the main agent is compiling, editing files, or running bash commands.
  • Operates Purely Ephemeral: Read-only, no tool execution, fast latency via Gemini Flash.

2. Architectural Comparison

Attribute Standard Turn (Enter / /plan) Ephemeral Turn (/btw <query>)
Session State Lock Acquires and holds promptLock in AntigravityAdapter Bypasses promptLock using isolated disposable text runtime
Persistence Stored in state.sqlite, turns table, conversation history 100% in-memory; discarded immediately on dismiss
Tool Execution Enabled (File I/O, bash commands, browser previews, MCP) Disabled (Zero side-effects, pure reasoning/retrieval)
Model Target User-selected thread model (Gemini Pro, Ultra, etc.) Fast tier default (Gemini Flash)
UI Placement Main conversation timeline stream Transient floating HUD / popover anchored above composer

4. Implementation Plan

Phase 1 Contracts & Protocols
  • Add ProviderEphemeralQueryInput and ProviderEphemeralQueryEvent to @t3tools/contracts.
  • Register BTW_SLASH_COMMAND in providerSnapshot.ts with input hint "your question".
  • Update composerSlashCommandSearch.ts to index and autocomplete /btw.
Phase 2 Server & Provider Layer
  • In AntigravityAdapter.ts, implement sendEphemeralQuery(threadId, prompt).
  • Extract recent turns & working context from active thread without acquiring promptLock.
  • Dispatch to disposable runtime (leveraging AntigravityTextGeneration.ts infrastructure).
  • Stream back chunks over WebSocket via ProviderService.sendEphemeralQuery.
Phase 3 Web & Desktop Client UI
  • Modify ChatComposer.tsx so typing /btw ... is not disabled during phase === "running".
  • Build BtwOverlayHUD.tsx floating card component anchored above the composer.
  • Handle Esc dismissal, copy-to-clipboard, and insert-into-composer actions.
Phase 4 Verification & Tests
  • Unit test AntigravityAdapter.test.ts: verify ephemeral query executes concurrently while an active turn is locked.
  • Unit test ChatComposer command parsing and submit interception.
  • End-to-end verification during an ongoing Antigravity turn.

5. Detailed Execution Flow

1. User types: /btw What port was chosen in vite.config.ts?
2. ChatComposer detects leading "/btw " command on submit.
3. ChatComposer opens BtwOverlayHUD in loading state and clears input.
4. Client issues RPC call: provider.sendEphemeralQuery({ threadId, prompt })
5. ProviderService dispatches to AntigravityAdapter.sendEphemeralQuery.
6. AntigravityAdapter reads recent thread context and cwd from session cache.
7. Adapter spawns lightweight Gemini Flash prompt (clientFileSystem=false, no terminal).
8. Streamed chunks emit as "provider.ephemeral-delta" events over WebSocket.
9. BtwOverlayHUD streams Markdown in real time.
10. User reads answer, hits Esc -> HUD unmounts -> Zero DB changes recorded.
